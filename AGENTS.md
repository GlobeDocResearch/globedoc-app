# Architecture rules
- Store avatar and licence references as object paths; resolve legacy public URLs only from the configured storage origin and obtain short-lived signed URLs through the authenticated owner-scoped Storage API so private files stay private.
- Store optional identity and pronouns on profiles so existing owner RLS, full-profile JSON export and profile deletion cover them; render saved identity via PatientIdentity with explicit translation exclusion, and exclude choice values from the generated label list.
- Keep logged-in header controls in WorkspaceBrand/WorkspaceBell (shared presentation, handlers page-owned): bell shows a red unread badge only when a count is passed (no notification source yet), sign-out hides below 640px (Settings/Profile keep it), and the professional badge is a round medical-bag icon on mobile with the "PRO" text pill on desktop.
- Keep the login entry presentation in a shared LoginEntryPage with audience variants so patient, professional, and legacy sign-in views preserve the same forms and appearance.
- /pro is a layout with a public index entry selected by matched route ID (not target pathname); authenticate only its workspace children and send successful professional sign-in to /connect to preserve the existing destination without mounting an auth guard during navigation.
- Use the Button plain variant when preserving pre-existing custom control styling without adding default button backgrounds.
- Scope public-entry typography and theme overrides to .entry-page so research-site styling does not alter the logged-in workspace.
- Keep installation presentation in InstallAppSection with browser lifecycle detection; never introduce app-shell caching for home-screen support.- Interface label list is generated by scripts/extract-interface-labels.ts (rerun after UI text changes); only these strings may be machine-translated in the logged-in app, to keep patient data away from translation services.
- Pairing redemption limits live in connect.pair.ts with a hashed-IP failed-attempt table and a per-code counter, and a DB trigger caps live codes per patient, because the backend has no rate-limiting primitive.
